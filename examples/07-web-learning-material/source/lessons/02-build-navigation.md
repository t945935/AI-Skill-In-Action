網頁教材不只是一組獨立頁面。讀者必須知道自己在哪裡、接下來去哪裡，以及如何只用鍵盤完成主要操作；製作者也要能證明內容與網站已通過交付前檢查。

## 使用語意化頁面結構

本範例的每一頁都有頁首、課程導覽、主要內容與頁尾。跳到主要內容連結放在頁面最前方，讓鍵盤及螢幕閱讀器使用者可以略過重複導覽。

課程導覽使用清單表達課次集合，並以 `aria-current="page"` 標示目前課次。上一課與下一課則放在正文之後，符合多數讀者的閱讀動線。

```html
<nav aria-label="課程目錄">
  <ol>
    <li><a href="lesson-1.html" aria-current="page">第一課</a></li>
    <li><a href="lesson-2.html">第二課</a></li>
  </ol>
</nav>
```

`aria-label` 說明導覽用途，`aria-current` 則讓目前位置不只靠顏色辨識。實際檔名應由課程設定產生，不要在多個頁面手動複製。

## 保留可見焦點

使用 `Tab` 鍵移動時，連結與按鈕需要有清楚的焦點外框。不要只靠顏色或滑鼠游標提示可操作元件，也不要用 CSS 移除 `outline` 卻沒有替代樣式。

## 小練習

建置網站後，不使用滑鼠完成下列操作：

1. 跳到主要內容。
2. 前往下一課。
3. 將目前課次標記為完成。
4. 回到課程首頁查看進度。

若焦點位置看不清楚，或操作順序不合理，就先修正模板，不要把問題留到部署後。

## 執行可重複的自動檢查

`run-case.ps1` 會重建網站，再檢查內容契約、頁面連結、語意地標、焦點樣式、本機資源與安全 fixture。完整案例必須通過；缺少學習目標與含有可執行內容的案例必須被阻塞。

自動檢查也會比較來源檔案雜湊，確認建置沒有改寫 Markdown 或 `course.json`。這讓 `source/` 保持為唯一可編輯來源，而 `site/` 可以隨時重新產生。

## 完成發布前人工走查

請至少檢查 375、768 與 1440 像素寬度，確認文字與元件沒有重疊或截斷；接著用鍵盤走完兩課，確認焦點、目前課次與完成狀態容易辨識。

記錄一項自動檢查可以發現的問題，以及一項只能靠人工閱讀發現的問題。兩類結果都確認後，才適合由負責人判斷是否部署。

## 本課小結

語意地標、清楚導覽與可見焦點共同構成可操作的教材基線。可靠的交付流程還會把自動檢查與人工判斷放在不同關卡；確認網址、授權、公開範圍與隱私設定後，才進入部署。
